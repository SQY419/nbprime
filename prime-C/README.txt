PrimeC v0.3
===========

A tiny self-hosted C compiler for the HP Prime (ARM926EJ-S / ARMv5TEJ).
Edit C code directly on the calculator, compile on-device, and run the
generated ARM machine code through the existing Prime ELF loader.

Directory
---------
main.py         MicroPython launcher / ELF loader (unchanged interface)
primec.py       C lexer, parser, ARMv5TEJ code generator, ELF writer
ccode.py        Edit this file directly on the calculator
ccode.elf       Generated by main.py (regenerate: host-side `make elf`)
tests/          Host-side ARM emulator + test suite (not used on-device)
Makefile        Host-side convenience targets

ccode.py format
---------------
Keep the C source between:

    /* PRIME-C-CODE-BEGIN */
    ...
    /* PRIME-C-CODE-END */

On the calculator:

    >>> import main

main.py reads ccode.py, calls compile_c() from primec.py, writes
ccode.elf, loads it with the shellcode loader and calls its entry point.
main()'s return value is printed.

Supported language (v0.4)
-------------------------
Types:            int, char (unsigned, 8-bit), void, pointers, arrays
                  (incl. multi-dim and incomplete-with-init), struct,
                  struct pointers, struct arrays
Globals:          int/char/pointer/array/struct globals with constant init
                  (= 5, = "str", = {1,2,3}, char* = "str")
Functions:        up to 4 parameters, recursion; structs must be passed
                  by pointer (by value rejected)
Statements:       if/else, while, do-while, for, switch/case/default
                  (with fallthrough), break, continue, return, blocks,
                  multi-declarator declarations
Expressions:      full C precedence; casts (int)/(char)/(T*)/(void)
                  + - * / % << >> & | ^ ~  == != < > <= >= && || ?:
                  = += -= *= /= %= <<= >>= &= |= ^=  ++ -- (pre/post)
                  & * [] . -> pointer/array/struct ops, string literals,
                  char literals, sizeof(type) / sizeof expr
Builtins:         __svc(imm, a0..a3) - firmware syscall (imm constant)
                  __sleep(ms)        - svc 0x00010008 (os_sleep)
                  strlen/strcmp/strcpy/memcpy/memset - builtin C library
                  (user definitions override)
                  printf(fmt, ...)   - format + print via the log ring
                  sprintf(buf, fmt, ...) - format into a buffer
Variadic:         functions may end with "..." (max 4 fixed params); the
                  fixed params go in r0..r3 and the extras on the stack;
                  int* va = (int*)__va_start(); reads them in order
Preprocessor:     #define NAME replacement (object-like macros)

Example:

    int fib(int n) { if (n < 2) return n; return fib(n-1) + fib(n-2); }
    int main() { return fib(12); }        /* prints 144 */

Returning a string:

    int main() { return "hello"; }

main() prints the numeric return value; if the value points into the
loaded image (string literals and globals live there), main.py also
reads it back and prints it as a string.

Semantics notes
---------------
* char is unsigned (loads are zero-extended, LDRB).
* Integer division truncates toward zero (C semantics); division by
  zero returns 0. Internal runtime helpers __aeabi_idiv / __aeabi_idivmod
  are generated into the image; no libgcc dependency.
* >> is an arithmetic shift on int (ASR), matching signed semantics.
* Call arguments are type-checked: passing a pointer/string where an
  int is expected (or the reverse) is a compile error, e.g.
  fib("abc") fails with "argument 1 of fib expects an int".
* Local arrays are not zero-initialized (as in C); local array
  initializers = {1,2,3} and = "str" are supported.
* Frame limit 32 KB per function; local addresses must fit the
  fp-relative 12-bit offset; the literal pool of a function must stay
  within 4095 bytes of every use.
* Globals/strings are addressed through relocated literal-pool words
  (R_ARM_RELATIVE), the same mechanism the PureDOOM ELF uses, so the
  existing shellcode loader handles them.

Firmware syscalls (IMPORTANT)
-----------------------------
The HP Prime G1 firmware does NOT return from svc normally: the SVC
handler pops the LR that the caller pushed and returns through it (the
"unconventional" CPU behaviour). Every syscall must therefore go
through a tiny wrapper:

    push {r0}
    push {lr}
    svc 0x00NNNN

which is exactly the shape of the sys_* wrappers in the DOOM port.
__svc() and __sleep() generate such a wrapper (one per distinct
immediate, appended to the image) and BL to it; arguments are placed
in r0..r3 and the result comes back in r0. Emitting a bare svc (as
earlier builds did) makes the handler pop a garbage LR and crash the
calculator.

Useful firmware numbers (HP Prime G1):

    0x10008 os_sleep(ms)     0x10037 malloc(n)     0x10038 calloc
    0x10039 realloc          0x1003a free(p)       0x1008d get_lcd
    0x100a5 get_time         0x100ca fclose         0x100cf fseek
    0x100d4 fread            0x100d7 fwrite         0x1026f fopen

These come from the firmware syscall table used by this project
(main.py resolves them at 0x307FBCAC). Wrong arguments to firmware
calls can still crash the calculator - test carefully.

printf / sprintf
------------------
Both format into a buffer with the conversions %d %i %u %x %X %c %s %p %%
plus optional width, '-' (left) and '0' (zero-pad). %u/%x operate on the
32-bit pattern (unsigned); %d prints INT_MIN correctly; %s copies the
string (the internal per-conversion scratch is 256 bytes - keep single
conversions below that).

printf() writes the formatted line into a log ring placed in the image:
    char __log_magic[8] = "PRIMELOG";   // offset 0
    int  __log_count;                   // offset 8
    char __log_data[4096];              // offset 12
main.py scans ccode.elf for the "PRIMELOG" magic, locates the ring at
runtime and prints its contents after main() returns.

Target details
--------------
* ARMv5TEJ (ARM926EJ-S), ARM state only, soft-float EABI.
* Generated ELF: ELF32 ET_DYN, single RWE PT_LOAD at vaddr 0, a
  PT_DYNAMIC with DT_REL / DT_RELSZ / DT_RELENT / DT_RELCOUNT and only
  R_ARM_RELATIVE relocations - exactly the shape the loader expects.
* main() is the entry point; it is called with (r0=0, r1=0).

Host-side testing (optional)
----------------------------
tests/emu_arm.py is a small ARMv5 interpreter and tests/run_tests.py
compiles ~80 C snippets with primec.py, runs them in the emulator and
checks the results. Not needed on the calculator:

    python3 tests/run_tests.py

v0.5 changes
------------
* variadic functions (int f(int a, ...)) - extras passed on the stack,
  read via __va_start(); up to 4 fixed params, any number of extras
* printf / sprintf with %d %i %u %x %X %c %s %p %% and width/flags;
  printf output goes to a "PRIMELOG" ring that main.py prints
* fixed: || short-circuit returned the inverted result (both exits set
  the wrong constant) - broke conv=='d' || conv=='i' and any || value
* fixed: mov_imm's byte-ORR fallback emitted ORR rd, r0, #imm instead of
  ORR rd, rd, #imm (garbage from r0 leaked into constants)
* fixed: vsformat's internal scratch buffer overflowed for %s strings
  longer than 24 chars (tmp is now 256, printf's line buffer 512)
* fixed: local addresses with non-encodable frame offsets now use a
  register (mov r1,#off; sub r0,fp,r1) instead of failing

v0.4 changes
------------
* casts (int)/(char)/(T*)/(void) - lets you use __svc-returned firmware
  addresses (e.g. the LCD framebuffer from svc 0x1008d) as pointers
* struct: definitions, . and ->, struct assignment, struct arrays,
  nested structs, sizeof; structs passed by pointer only
* switch/case/default with fallthrough; break/continue reworked onto
  separate break/continue target stacks
* builtin small library (strlen/strcmp/strcpy/memcpy/memset) compiled
  from C source by the compiler itself; user code may override them
* multi-dim arrays (int m[2][3]), including flat initializers
* static locals (persistent per-function storage in .data)
* #define object-like macros (recursion depth-capped); #include and
  function-like macros are rejected with clear errors
* fixed: `d[i] = s[i]` style assignment now leaves the assigned value
  in r0 (previously the address) - broke while ((d[i]=s[i])) loops

v0.3 changes
------------
* int/char/void types, pointers, arrays, string literals, globals
* break/continue/do-while, ++/--, compound assignment, bitwise/shift
  ops, ternary, short-circuit &&/|| (v0.2 evaluated both sides)
* __svc / __sleep firmware builtins (fix: syscalls now go through
  push{r0}/push{lr}/svc wrappers - the firmware returns via the pushed
  LR, a bare svc crashed the calculator; verified on hardware)
* call-argument type checking (fib("abc") is now a compile error)
* main.py prints returned strings (pointer into the image) as text
* fixed v0.2 bugs: SUB without S flag in the division loop (infinite
  loop), negative frame offsets never emitted (locals clobbered the
  saved lr and the return jumped to garbage), division quotient never
  shifted, remainder sign flag clobbered by the loop
* literal pool with R_ARM_RELATIVE relocations for globals/strings
